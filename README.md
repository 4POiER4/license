# Лицензии — реестр программного обеспечения отдела

Веб-приложение для Linux-сервера организации. Django, PostgreSQL, Gunicorn и WhiteNoise; запуск через Docker Compose. Браузеру не нужны интернет, расширения или внешние шрифты.

## Что реализовано

- Общая локальная учётная запись отдела, вход и смена пароля.
- Договор: номер, дата заключения, необязательный контрагент, общая сумма, валюта и примечание.
- В одном договоре несколько позиций ПО. У каждой: название, количество лицензий, стоимость **всего количества**, дата начала и окончания либо бессрочность.
- Валюты BYN, RUB и USD. Валюта задаётся договору и распространяется на его позиции. Итоги разных валют не складываются и не конвертируются. Для сохранённого договора валюта закреплена, чтобы исторические суммы не изменили смысл.
- Общая сумма договора вводится отдельно; стоимость ПО и разница рассчитываются точно, с двумя знаками после запятой. Разница позволяет учитывать услуги. Превышение суммы позиций над суммой договора отмечается предупреждением и не блокирует сохранение.
- Поиск по ПО, номеру договора и контрагенту; фильтры статуса и валюты; страницы по 30 записей; экспорт отфильтрованного реестра в CSV с BOM и разделителем `;`.
- Продление по существующему или новому договору. Предыдущий период остаётся отдельной записью; карточка показывает всю цепочку продлений. Повторное продление одного периода блокируется.
- Договоры и периоды остаются в реестре после истечения. Удаление через интерфейс не предусмотрено, чтобы не терялась история.

## Правила сроков

Дата окончания включается в срок действия. Часовой пояс — `Europe/Minsk`.

Начало напоминаний: **дата окончания минус два календарных месяца**, включая получившийся день. Если в целевом месяце такого числа нет, берётся последний день месяца. Например, для окончания 30 апреля напоминание начинается 28 февраля (29 февраля в високосный год).

Уведомление показывается по дату окончания **плюс пять дней включительно**. Например, для окончания 10 ноября оно остаётся до 15 ноября включительно и исчезает 16 ноября. Запись продолжает отображаться красным со статусом «Срок истёк».

Красная подсветка включается с начала периода напоминаний и остаётся после истечения. Бессрочные лицензии не требуют напоминаний. Будущая лицензия имеет статус «Ещё не началась»; если её дата окончания уже попадает в окно напоминаний, предупреждение всё равно появляется.

На главной странице есть постоянный блок напоминаний. При входе в учётную запись и первом открытии реестра в новой вкладке дополнительно показывается окно. Закрытие окна действует только в текущей вкладке, не отключает уведомления для коллег и не отменяет напоминание при следующем входе. Если интерфейс оставлен открытым на ночь, обновите страницу: сроки пересчитываются при каждом запросе. Фоновый планировщик и почтовый сервер не нужны.

Продление не изменяет напоминания предыдущего периода: согласно общему правилу они прекращаются через пять дней после его окончания. В уведомлении показано, что у записи уже есть продление.

## Быстрый локальный запуск

Нужны Docker Engine, Docker Compose v2 и Python 3 (только для создания конфигурации). Для первого скачивания образов и пакетов нужен интернет.

```bash
./run-local.sh
```

Адрес: **http://localhost:8096**. Порт можно изменить в `.env`.

Первый запуск создаёт `.env` со случайными секретами и `.local-access.txt` с логином `department` и начальным паролем. Оба файла доступны только владельцу и исключены из Git и Docker-образа. Пароль не выводится в логи. Смените его в меню учётной записи внизу слева. Перезапуск не сбрасывает уже изменённый пароль. Файл начального доступа после смены пароля не обновляется.

Рабочая база изначально пустая. Тестовые данные автоматически не добавляются.

```bash
docker compose ps
docker compose logs --tail=100 web
docker compose stop
docker compose up -d --wait
```

Данные PostgreSQL хранятся в постоянном Docker-томе `license-registry_database`. Команда `docker compose down` сохраняет том; **`down -v` удаляет данные**.

## Развёртывание на сервере организации

Готовый архив исходников создаётся командой `python3 scripts/package.py` в `outputs/license-registry-source.tar.gz`. Секреты, база, резервные копии и снимки экрана в архив не входят. Проверки описаны в `VERIFICATION.md`.

1. Скопируйте исходники на сервер. Не переносите локальные `.env`, `.local-access.txt`, `.git`, `.venv`, `backups` и `test-results` в общий доступ.
2. Выполните `python3 scripts/init_env.py` для генерации новых серверных секретов.
3. Отредактируйте `.env`, указав реальный адрес сервера. Пример для внутренней сети:

```dotenv
BIND_ADDRESS=0.0.0.0
APP_PORT=8096
DJANGO_ALLOWED_HOSTS=licenses.company.local,192.168.1.20,localhost,127.0.0.1
DJANGO_CSRF_TRUSTED_ORIGINS=http://licenses.company.local:8096,http://192.168.1.20:8096
```

4. Запустите `./run-local.sh`. Разрешите порт 8096 только из сети отдела согласно правилам организации. PostgreSQL не публикует порт на сервере.
5. Откройте `http://АДРЕС-СЕРВЕРА:8096` с рабочего места. Войдите с серверным начальным паролем и смените его.

Для HTTPS используйте существующий reverse proxy организации. Сохраните привязку приложения к `127.0.0.1`, задайте домен в `DJANGO_ALLOWED_HOSTS`, а `https://домен` — в `DJANGO_CSRF_TRUSTED_ORIGINS`. Установите `DJANGO_SECURE_COOKIES=1`. Не включайте `DJANGO_SSL_REDIRECT=1` за прокси без настройки доверенного определения HTTPS, иначе возникнет цикл перенаправлений. В текущей конфигурации заголовки прокси не считаются доверенными: TLS заканчивается на прокси, а принудительное перенаправление HTTP→HTTPS настраивается на нём.

После изменения `.env`: `docker compose up -d --force-recreate web`.

Если забыли пароль, администратор сервера может интерактивно сменить его без вывода в командную строку:

```bash
docker compose exec web python manage.py changepassword department
```

Одна учётная запись означает общие данные и права редактирования. Действия отдельных сотрудников не различаются. Это согласованный режим для отдела.

## Резервное копирование и восстановление

```bash
./scripts/backup.sh
```

Создаётся архив PostgreSQL `backups/licenses-ДАТА-ВРЕМЯ.dump`, доступный только владельцу. Копируйте резервные копии на отдельное защищённое хранилище. Секреты из `.env` и конфигурацию сервера сохраняйте отдельно. В архив базы входят также учётная запись и её пароль в виде хеша.

Восстановление перезаписывает данные выбранной базы. Сначала сделайте резервную копию текущего состояния и остановите web. Пример для собственного сервера:

```bash
docker compose stop web
docker compose exec -T db pg_restore -U licenses -d licenses --clean --if-exists --no-owner < backups/ИМЯ-ФАЙЛА.dump
docker compose up -d --wait web
```

Для регулярных копий можно использовать cron сервера с абсолютным путём к `scripts/backup.sh`. Расписание не создаётся автоматически.

## Проверки

Тесты создают отдельную тестовую базу и не используют рабочие записи:

```bash
docker compose run --rm web python manage.py test
docker compose run --rm web python manage.py check
docker compose run --rm web python manage.py makemigrations --check --dry-run
node --check static/app.js
```

Для проверки на SQLite:

```bash
docker compose run --rm -e DB_HOST= web python manage.py test
```

Проверка настроек для HTTPS: `docker compose run --rm -e DJANGO_SECURE_COOKIES=1 -e DJANGO_SSL_REDIRECT=1 web python manage.py check --deploy`. Для локального HTTP отключены secure-cookie, HSTS и принудительное HTTPS: `check --deploy` без этих переменных сообщает ожидаемые замечания.

## Отдельная демонстрационная среда

Нужна только для проверки интерфейса. Имеет собственную базу и порт; не изменяет рабочий реестр:

```bash
docker compose -p license-registry-qa -f compose.yaml -f compose.qa.yaml up -d --no-build --wait
docker compose -p license-registry-qa -f compose.yaml -f compose.qa.yaml exec web python manage.py seed_demo
```

Адрес http://localhost:8097, тестовый логин `review`, пароль `Review-only-2026-password`. Тестовый пароль предназначен только для этой изолированной среды на loopback. Все примеры вымышленные и отмечены соответствующим баннером. Команда заполнения отказывается работать без явного разрешения и в непустой базе.

```bash
docker compose -p license-registry-qa -f compose.yaml -f compose.qa.yaml down
```

## Обновление

Перед обновлением сделайте резервную копию. Затем замените исходники и выполните `./run-local.sh`: образ пересоберётся, миграции применятся автоматически, база останется в томе. Зависимости закреплены в `requirements.txt`; обновления Django и других библиотек устанавливаются после проверки и повторного запуска тестов.

Документация по настройке развёртывания: https://docs.djangoproject.com/en/5.2/howto/deployment/checklist/.
